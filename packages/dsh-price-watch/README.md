# @ultraslow/dsh-price-watch

在 DeepSeek Harness Web UI 里盯**机票和酒店**价格，价格有变化时通过飞书推送卡片。

机票有两种模式，**有没有定日期，决定了它怎么工作**：

- **没定日期 → 行情模式**：只看「北京→上海 未来一年哪天最便宜」。用携程公开的免登录日历接口，一次请求拿到 ~380 天每天的最低价，画成日历柱状图，点某一天就能「钉住」变成监控。
- **定了日期 → 监控模式**：盯住这一组日期，每次都走登录态真实页面（L2），读出**具体航班**（航班号 / 航司 / 时刻 / 机场 / 机型）和**每位乘客按身份能买到的实付价**。

酒店是**第三种模式**（`mode: 'hotel'`）：一家酒店、一段固定住期，按你选的节奏读取房型价格，记录「这段住期的最低整段总价」。

## 两模式对照

| | 行情模式（没定日期） | 监控模式（定了日期） |
| --- | --- | --- |
| 回答的问题 | 哪天走最便宜？ | 这几个航班现在多少钱？ |
| 数据源 | 只用 L1（免登录日历） | 只用 L2（登录态真实页面） |
| 图表 | x = 日期，y = 当日最低含税价 | x = 采集时间，y = 乘客级实付价 |
| 刷新 | 30 分钟 / 1 小时 / 3 / 6 / 12 / 24 小时（默认 6 小时） | 同一套档位（默认 6 小时） |
| 需要登录 | 不需要 | 需要（登录携程后才采得到） |
| 告警 | 静默（只做看板） | 新低 / 新高 / 异常 / 日报 |

> 行情模式不告警是刻意的：380 个日期里几乎每天都有某一天刷新低，按「新低就报」会被直接淹没。

## 能做什么

- **侧栏常驻入口**：左侧栏出现一个价格标签图标，点开就是整页面板（不是悬浮层）。面板顶部按「机票 / 酒店」分 tab，机票下再按「行情 / 监控」筛选。
- **行情日历**：单程一张、往返两张（去程 / 回程）柱状图，最低价柱高亮，鼠标悬停看具体价格，点柱子就能「钉住这天」创建监控。
- **监控走势**：每轮采集的「最低可订价」合并成一张折线图（不按乘客拆图）；往返监控另有「联程组合 vs 两段单买」对比卡。
- **可订航班表**：最近一次采集到的 TOP10 航班（航班号 / 航司 / 时刻 / 机场 / 机型 / 实价 / 余票 / 状态），最低价行高亮；往返监控拆成「联程组合列表 / 去程 / 返程」三块。
- **乘客名单**：在设置里维护乘客（昵称 / 成人·学生·儿童 / 年龄），新建时多选；学生票、老年票、儿童票都按「带条件的票价产品」筛选。
- **酒店监控**：城市 + 酒店名称 + 住期 + 入住人数，新建时**先去携程校验酒店是否存在**；通过后按节奏读取房型价格，记录「该住期最低整段总价」的走势。
- **酒店房型快照**：每次采集保存当时所有可订房型（房型 / 床型 / 面积 / 每晚 / 整段），按整段升序、最低价高亮。
- **酒店飞书卡片**：一张卡片四块——结论（整段最低总价 + 每晚约 + 房型 + 酒店名/星级/评分 + 涨跌）、走势（图 + 统计）、房型价格表（前 6 个 + 「另有 N 个」）、本次采集。
- **频率完全由你决定**：每 30 分钟到 24 小时之间自选，不设每日次数上限、没有静默时段、也不做自动降频。调度带 ±15% 抖动，模拟人的节奏；被携程风控挡住时该监控自动跳过一轮，不会连续硬撞。
- **每次采集推一张卡片**：行情/监控/酒店各有一套**卡片 2.0**，按「结论 / 走势 / 明细 / 采集信息」四块分区展示——价格主视觉（实价 + 涨跌幅，跌绿涨红）、联程组合 vs 两段单买对比、联程组合列表或可订航班表（含余票）、带**横纵坐标刻度**的走势图（X 轴日期、Y 轴金额、最高/最低金额标注，最低点绿 / 最高点红；纯 JS 矢量渲染，内嵌 OFL 字体子集，不启动浏览器、无原生依赖）；**采集结果与上次相同则不推**，不设冷却也不做重试（价格/房型没变化时，点「立即采集」也不会重复发消息）。
- **手机可看**：`/price-watch/` 是独立的只读 HTML 页面，同局域网手机直接打开，不依赖 DSH 前端。

## 酒店价格监控

酒店没有「有没有日期」之分：每条酒店监控就是**一家酒店 + 一段住期**，每次采集给你这段住期的最低整段总价和房型列表。

**需要输入**

1. 城市（复用机票那份城市库，中文名或三字码都可以）
2. 酒店名称：**边输入边联想**——**先选城市**，再输入 2 个字以上，下拉会实时列出该城市里匹配的门店（名称 / 商圈 / 档次），↑↓ 选择、Enter 或点击确认；选中后锁定具体门店 id，提交时不再需要名称匹配。也可以不选、直接手填全名（只写品牌时会提示你选具体门店）
3. 入住日期 / 离店日期（1–30 晚，离店必须晚于入住）
4. 入住人数（1–6 人，固定 1 间）
5. 采集节奏（在「高级选项」里，30 分钟–24 小时，默认跟随设置里的监控节奏）

**新建时会先去携程校验酒店是否存在**（校验通过才落库，随后立即采集一次）：

- 找不到这家酒店 → 表单里显示错误原文（`HOTEL_NOT_FOUND`），不创建、不采集；
- 只写品牌（如「全季酒店」）匹配到多家分店 → 返回 `HOTEL_AMBIGUOUS` + 提示「这是品牌名，请选择具体门店」，表单里列出候选（名称 / 地址），**点一下候选就直接建那家**；也可以把名字写完整（如「全季酒店 虹桥」）再试；
- 联想选中后又改了名称再提交 → 返回 `HOTEL_LOOKUP_STALE`，清掉已选门店让你重选，避免「看着 A 建成 B」；
- 网络问题 → `502`，稍后再试。

联想和校验都是**纯 HTTP 直接问携程**（不开浏览器、不需要登录）：联想单次约 0.2–0.8 秒（写品牌时会自动补上城市名再查一次，所以像「全季」也能出具体门店）、选中具体门店后创建约 0.2–0.3 秒；靠名称匹配时约 0.7–2.2 秒。提交按钮在这段时间显示「正在校验酒店…」。

**采到什么**：用**机票那份已登录的同一个浏览器 profile** 读取携程房型价格（不登录看不到房价）。每次采集记录 **1 个价格点**：该住期的最低整段总价；同时保存一份房型快照。

| 房型 | 床型 | 面积 | 每晚 | 整段 |
| --- | --- | --- | --- | --- |
| 大床房（电视投屏） | 1张1.51米大床 | 18平方米 | ¥299 | ¥598 |

> 示例：全季酒店(上海虹桥中山西路店)，2026-12-05 → 12-07、2 人，实测 4 个可订房型，最低整段 **¥598**（每晚 ¥299，房型「大床房（电视投屏）」），评分 4.6「很好」。首次采集约 2–3 秒（浏览器会话已热）；新建时点选联想门店只需约 0.3 秒。价格随日期和房态变化，这里只是当时的示例。

房型表按整段升序、最低价高亮；**v1 不区分**含早 / 可取消 / 会员价，也不做房型聚合去重。

**价格走势**：x = 采集时间，y = 该住期最低整段总价；复用机票那套纯 JS 矢量渲染（不启动浏览器、无原生依赖），最低点绿、最高点红。

**必须登录携程**：酒店价格属于登录态数据。登录态失效时采集会失败并提示「酒店价格需要携程登录」，详情页里有「登录携程」按钮；登录后点「立即采集」即可。

**过期自动删除**：离店日期早于今天的酒店监控会被静默删除（与机票同策略），不发卡片。

**酒店与机票监控的差异**

| | 机票（行情 / 监控） | 酒店 |
| --- | --- | --- |
| 数据源 | 行情 = 免登录日历；监控 = 登录态浏览器 | 全程登录态浏览器（读房型价格） |
| 图表 | x = 日期（行情）/ x = 采集时间（监控），y = 最低可订价 | x = 采集时间，y = 该住期最低整段总价 |
| 乘客 | 监控模式要选乘客（身份影响票价） | 只要入住人数，不要姓名 |
| 新建校验 | 本地校验三字码与日期 | 额外到携程**远端校验**酒店是否存在 |

**v1 已知限制**：只支持 1 间房；不区分含早 / 可取消 / 会员价；不支持多日期区间比价；联想只按酒店名（不按地标/地铁站找酒店）。

## 安装方式

```sh
dsh plugin add @ultraslow/dsh-price-watch
```

或者从本仓库安装本地目录：

```sh
dsh plugin add ./packages/dsh-price-watch
```

装完重启 DSH，左侧栏会出现价格标签图标。

**监控模式与酒店模式的可选依赖**：插件用 `playwright-core` 驱动你本机已安装的 Chrome（不下载 Chromium）。没装 Chrome 或没登录时，行情模式照常可用（只走免登录日历），监控模式和酒店模式会显示「采集不可用」。

## 使用

1. 侧栏点开「价格监控」→ `＋ 新建`
2. 填出发地 / 目的地：可以输入三字码（`BJS`）也可以输入城市名（`北京`），会给出候选
3. 选单程或往返
4. **决定要不要定日期**：
   - 不定 → 行情模式，接下来只追踪「未来一年每天最低价」
   - 定 → 监控模式，单程填 1 个日期、往返填 2 个
5. 勾选乘客（没有的话先去 `设置 → 乘客` 添加），至少一位
6. 保存后立即开始首次采集；行情模式几分钟内出整张日历
7. 要收飞书通知，二选一：
   - **企业自建应用（推荐，能推图表）**：开放平台建应用 → 开 `im:message:send_as_bot` + `im:resource` 权限 → 发布版本 → 机器人拉进群 → 设置页填 App ID / App Secret / 群 chat_id → 点「发送测试消息」验证
   - **自定义机器人（最简单）**：群里添加自定义机器人 → 复制 webhook → 设置页填 webhook。这条通道不能推图片，卡片只有文字
8. 要用监控模式：`设置 → 用户登录` → 点「登录携程」→ 在弹出的 Chrome 窗口里扫码/手机号登录（插件不接触密码和验证码）→ 检测到登录态后窗口自动收走
9. 频率在新建时的「高级选项 → 采集节奏」里选，也可以随时在详情页改

### 酒店监控

1. 面板顶部切到「酒店」tab → `＋ 新建酒店监控`
2. 填 5 项基础信息：城市 / 酒店名称 / 入住日期 / 离店日期 / 入住人数；采集节奏在「高级选项」里，默认跟随设置里的监控节奏，可以不动
3. 输入酒店名时下拉会实时出候选；点选一家（或直接手填全名）后提交，按钮显示「正在校验酒店…」，插件会问一次携程确认这家酒店存在（点选门店约 0.3 秒，按名称匹配约 0.7–2.2 秒）
4. 成功后面板直接跳到该监控详情，页面里显示「已匹配：酒店全名」；失败时错误原文显示在表单里，**不会落库**
5. 详情页自上而下：酒店抬头（名称 / 星级 / 评分 / 地址）→ 最低整段总价（+ 每晚约，右侧「立即采集」可手动跑一次）→ 走势图 → 房型价格表（最低价整行高亮，不再额外标注）→ 采集节奏（节奏 + 下次采集，与机票一致）

> 登录态保存在独立的浏览器 profile 里（`~/.dsh/price-watch/browser-profile/`），不写进任何 JSON，也不会动你日常用的 Chrome。删掉该目录等于退出登录。机票监控和酒店监控共用这一份登录态。

## 数据与隐私

所有数据都在本机 `$DSH_HOME/price-watch/`（通常是 `~/.dsh/price-watch/`）：

```
config.json      乘客名单、采集频率、通知设置
monitors.json    监控任务（机票与酒店）
state.json       调度游标、下次采集时间、登录态、投递状态
calendar/*.json  行情模式的整份日历快照
flights/*.json   监控模式最近一次采集到的航班快照
hotels/*.json    酒店模式最近一次采集到的房型快照
prices/*.jsonl   价格序列（机票监控与酒店共用同一套序列格式）
alerts.jsonl     最近的投递记录
```

- L1 只访问携程的公开日历接口，不需要登录、不读取你的订单、不上传任何数据。
- L2 与酒店都用你自己登录的浏览器会话，只读取航班列表 / 房型价格与订单页税费，**永不提交订单、永不与验证码对抗**。
- 飞书凭据（webhook 或 App ID/Secret/群 chat_id）只存在本机 `config.json`，只用于发送卡片；接口读出来会脱敏（只回「是否已设置」），插件不会读取你飞书里的任何内容。
- 删掉 `$DSH_HOME/price-watch/` 即可清空全部数据。

## 边界（重要）

- **L1 的数字是「市场最低参考价」，不是「你能订的价」**。L1 不知道你是谁，当天最低价可能来自「限 55 岁以上 + 至少 3 人」的条件票。真正的可订价只有 L2 能给。
- **行情模式不告警**，它只是选日期的工具。要提醒就把日期钉住，变成监控模式。
- **L1 只支持单程**：往返的 L1 数字是「去程最低 + 回程最低」相加的估算，通常比真实联程票贵；真实往返价要靠 L2。
- **价格口径**：L1 给的是「单张票含税总价」；L2 给的是「你们这几位乘客各自能买到的含税实付价」。两者不要混着看。
- **监控模式没有 L1 兜底**：它是纯 L2 口径，采集失败（风控/登录过期/页面变化）时只会记失败，价格序列会留一段空洞——不会用日历估算价填进去，避免两种口径混在一张图里。
- **酒店 v1 只支持 1 间房**，不区分含早 / 可取消 / 会员价，也不做多日期区间比价；酒店名匹配到多家时可以在候选里点选（表单已带实时联想）。
- **不做验证码对抗**：遇到风控只会跳过一轮并在界面显示原因，不会硬刚。

## 故障排查

| 现象 | 排查顺序 |
| --- | --- |
| 侧栏没有图标 | profile 里是否有 `link:` 依赖 → `dsh.profile.bundles` 是否含本包名 → 重启日志是否跳过该 bundle（`engines.dsh` 不满足会被跳过）→ 页面是否刷新过 |
| 面板打开但显示「读取失败」 | 打开 `http://127.0.0.1:<端口>/price-watch/api/status` 看返回；再看 DSH 终端里 `[price-watch]` 开头的日志 |
| 行情日历是空的 | 该航线可能没有报价；换个城市对试试。日历接口偶尔限频，等一个周期会自动恢复 |
| 监控模式一直失败 | 没登录 / 登录过期 / 携程页面结构变了。看详情页「采集节奏」里的上次失败原因 |
| 酒店提示「酒店价格需要携程登录」或一直失败 | 酒店价格必须登录才可见：先 `设置 → 用户登录` 点「登录携程」完成登录，再回酒店详情点「立即采集」 |
| 新建酒店时报 `HOTEL_AMBIGUOUS` | 携程匹配到多家分店：表单里会列出候选（名称 / 地址），**点一个就直接创建**；也可以把酒店名写完整（带上分店名/路名）再提交 |
| 新建酒店时报 `HOTEL_NOT_FOUND` | 该城市/日期段查不到这家酒店：确认城市选对、酒店名没有错别字；换一个日期段或把名字写得更常见再试 |
| 飞书收不到 | 先在设置页点「发送测试消息」看返回的原始错误：`code=… msg=…`。常见原因：Webhook 不是 `https://`、自定义机器人开了签名校验（本插件不支持签名）、自建应用没开 `im:message:send_as_bot` 权限、机器人没被拉进目标群、chat_id 不对 |
| 显示「采集不可用」 | `playwright-core` 没装上，或本机没有 Chrome。重装插件即可；行情模式不受影响 |
| 早上看到「page.goto: Timeout …」或「网络不可用」 | 笔记本合盖/空闲休眠时，系统只在「维护唤醒」里醒几秒又睡回去，采集会因进程被挂起而超时。插件已识别这类失败：**不推失败卡**，只记到面板并在 **15 分钟后补采**；想让它通宵稳定采集，请在「系统设置 → 锁定屏幕 / 电池」里关掉自动睡眠 |
| 一直采不到、提示被风控 | 携程限频了，插件会让这个监控跳过一轮；持续被拦就把频率调大（比如从 30 分钟改成 1 小时以上） |
| 点「登录携程」没弹窗 | 检查是否有残留 Chrome 进程占着 profile（`pkill -f price-watch` 后重试）；或本机 Chrome 被安全软件拦截 |
| 登录后仍显示「未登录」 | 点一下状态条的登录 chip 触发复查；仍不行就「退出登录」再登一次 |

## 开发与验证

```sh
node --check index.js && node --check client.js
node --test                       # 75 条单测（票价规则 / 卡片 / 走势图 / 酒店解析 / 酒店存储 / 酒店卡片 / 网络分类）
node ../../.dsh/skills/dsh-plugin-dev/scripts/check-plugin.mjs .
```

纯 ESM、无构建步骤：`index.js` 是 Host 半边，`client.js` 是浏览器半边（`window.__ModuleLoader__.load`），`host/` 下是 Host 的各个模块。

## 文件结构

```
packages/dsh-price-watch/
├── index.js                 Host 入口：路由注册 + 60s 心跳调度（频率由每个监控自己的 cadence 决定）
├── client.js                浏览器半边：侧栏图标 + 整页面板（机票行情/监控 + 酒店视图）
├── host/
│   ├── store.js             持久化（原子写、损坏自愈、旧 schema 迁移）
│   ├── collect/index.js     采集编排（行情 / 监控 / 酒店三条路径）
│   ├── collect/calendar.js  L1：携程公开最低价日历
│   ├── collect/browser.js   L2：登录态浏览器读航班列表 + 票价产品
│   ├── collect/hotel.js     酒店：新建校验 / 房型价格采集 / 健康探针
│   ├── net.js               采集前网络探针与网络错误分类
│   ├── notify.js            卡片构造（行情 / 监控 / 酒店 / 失败 / 测试）
│   ├── card.js              飞书卡片 2.0 积木
│   ├── feishu.js            飞书投递：token / 图片上传 / 发群消息
│   ├── chart.js             纯 JS 生成走势图（不启动浏览器、无原生依赖）
│   ├── chart-font.js        走势图内嵌的矢量字体子集
│   ├── OFL-Inter.txt        Inter 字体子集的许可证（OFL）
│   ├── routes.js            HTTP 路由与同源校验
│   ├── page.js              独立只读 HTML 页面
│   └── util.js              日期、ID、日志、城市名等小工具
├── test/                    node --test 单测（75 条）与 fixtures
├── locale/{zh,en}.json      插件管理器的展示文案
├── icon.svg
├── cordis.patch.yml
└── README.md
```
