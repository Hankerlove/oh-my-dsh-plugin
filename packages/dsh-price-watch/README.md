# @ultraslow/dsh-price-watch

在 DeepSeek Harness Web UI 里监控机票价格：选好航线和日期，插件按计划采集携程的公开最低价日历，留存价格历史，在侧栏面板里画走势图，价格跌破目标价、创出新高或新低时通过飞书推送提醒。

## 能做什么

- **侧栏常驻入口**：左侧栏出现一个价格标签图标，点开就是整页监控面板（不是悬浮层）。
- **锁定日期监控**：单程填一个出发日，往返填出发日 + 返回日，插件只盯这一组日期，采集成本极低。
- **价格历史**：每次采集写入一条 JSONL 记录，面板画时间-价格折线，并标出历史最低、历史最高、7 日均价和目标价。
- **提醒规则**：目标价（跌破才提醒，回到上方重新武装）、历史新低、历史新高、每日摘要；同一规则有 6 小时冷却，新高/新低每天只推一次，避免刷屏。
- **飞书卡片**：推送带「查看走势」按钮，指向插件自带的只读页面。
- **手机可看**：`/price-watch/` 是一个独立的只读 HTML 页面，同局域网的手机直接打开，不依赖 DSH 前端。
- **乘客名单**：在设置里维护乘客（昵称 / 成人·学生·儿童 / 年龄），新建监控时勾选；价格按单张票展示，不乘人数。
- **精确采集（需登录携程）**：用一个真实浏览器窗口读取携程的票价产品，按乘客**年龄**筛选（学生票、老年票、儿童票都是"带年龄区间的票价产品"），并在订单页读取 `票价 / 机建 / 燃油 / 总价` 的真实拆分。每天次数可配，默认 1 次。
- **风控自我保护**：识别到"列表被限频/验证页"时自动暂停精确采集（2 小时退避），期间继续用日历估算价，并推一条告警。

## 安装方式

```sh
dsh plugin add @ultraslow/dsh-price-watch
```

或者从本仓库安装本地目录：

```sh
dsh plugin add ./packages/dsh-price-watch
```

装完重启 DSH，左侧栏会出现价格标签图标。

**精确采集的可选依赖**：插件用 `playwright-core` 驱动你本机已安装的 Chrome（不下载 Chromium，约 14MB）。没有装 Chrome 或不想要浏览器采集时，插件仍然可用，只是退化为日历估算价——面板上会显示「精确采集不可用」。

## 使用

1. 侧栏点开「价格监控」→ `＋新建监控`
2. 填出发地 / 目的地（三字码，如 `BJS`、`SHA`）、单程或往返、日期
3. 勾选乘客（没有的话先去 `设置 → 乘客` 添加）
4. 可选：填目标价
5. 保存后 30 秒内会完成首次采集；之后按采集频率（默认 30 分钟）自动更新
6. 要收飞书通知：在飞书里建一个只有自己的群 → 添加「自定义机器人」→ 复制 webhook → 粘贴到 `设置 → 飞书 webhook` → 保存
7. 要开精确采集：`设置 → 精确采集` 打开开关 → 点「登录携程」→ 在弹出的 Chrome 窗口里扫码/手机号登录（插件不接触密码和验证码）→ 检测到登录态后窗口自动收走。之后只在登录过期时才需要重新授权

> 登录态保存在独立的浏览器 profile 里（`~/.dsh/price-watch/browser-profile/`），不写进任何 JSON，也不会动你日常用的 Chrome。

## 数据与隐私

所有数据都在本机 `$DSH_HOME/price-watch/`（通常是 `~/.dsh/price-watch/`）：

```
config.json     乘客名单、采集频率、通知设置
monitors.json   监控任务
state.json      调度游标、规则冷却时间
prices/*.jsonl  每个任务一条价格序列
alerts.jsonl    最近的通知记录
```

- 只访问携程的公开日历接口，不需要登录、不读取你的订单、不上传任何数据。
- 飞书 webhook 只用于发送提醒卡片；插件不会读取你飞书里的任何内容。
- 删掉 `$DSH_HOME/price-watch/` 即可清空全部数据。

## 边界（重要）

- **价格口径**：采集的是**单张票的含税总价（日历估算）**，不是最终成交价。真实下单价以下单页为准。
- **数据来源**：使用携程公开最低价日历，作为 OTA 大盘的价格代理。如果你在智行 App 看到的价格更低（券后价、专属补贴），插件显示的数字会偏高——这是刻意的取舍，插件只看趋势，不追求与最终下单价一致。
- **暂无酒店、暂无往返真实联程价**：往返目前的数字是「去程最低价 + 返程最低价」的估算，真实联程价需要浏览器采集（已在路线图上）。
- **精确采集是"客"(guest)，不是"主"**：携程的列表接口对高频访问很敏感。连续调试几次就可能触发限频（页面壳正常、日期条有价、但航班行为空）。插件会自动退避 2 小时并继续用日历估算价，因此**价格趋势不会断**，但精确价会暂停。
- **淡季和高频访问会被拦**：默认每天只精确采集 1 次；调高次数会显著提高被风控的概率。
- **采集失败会告警**：连续 3 次采集失败推送一次 critical 提示，避免监控静默死亡。
- **不做验证码对抗**：遇到风控只会退避并提示，不会硬刚。

## 故障排查

| 现象 | 排查顺序 |
| --- | --- |
| 侧栏没有图标 | profile 里是否有 `link:` 依赖 → `dsh.profile.bundles` 是否含本包名 → 重启日志是否跳过该 bundle（`engines.dsh` 不满足会被跳过）→ 页面是否刷新过 |
| 面板打开但显示「读取失败」 | 打开 `http://127.0.0.1:<端口>/price-watch/api/status` 看返回；再看 DSH 终端里 `[price-watch]` 开头的日志 |
| 一直采集不到价格 | 该航线/日期可能确实没有报价；换个日期试试。日历接口偶尔限频，等一个周期会自动恢复 |
| 飞书收不到 | webhook 是否以 `https://` 开头；飞书机器人是否开启了签名校验（本插件不支持签名，请在机器人设置里关掉或改用关键词校验）；`设置` 里是否点了保存 |
| 显示「精确采集不可用」 | `playwright-core` 没装上，或本机没有 Chrome。重装插件即可；只用估算价可以忽略 |
| 显示「风控暂停至 …」 | 携程限频了，插件会自动退避 2 小时后重试；这段时间用日历估算价，不用处理 |
| 点「登录携程」没弹窗 | 检查是否有残留的 Chrome 进程占着 profile（`pkill -f price-watch` 后重试）；或本机 Chrome 被安全软件拦截 |
| 登录后仍显示「未登录」 | 点一下状态条的登录 chip 触发复查；仍不行就「退出登录」再登一次 |

## 开发与验证

```sh
node --check index.js && node --check client.js
node ../../.dsh/skills/dsh-plugin-dev/scripts/check-plugin.mjs .
```

纯 ESM、无构建步骤：`index.js` 是 Host 半边，`client.js` 是浏览器半边（`window.__ModuleLoader__.load`），`host/` 下是 Host 的各个模块。

## 文件结构

```
packages/dsh-price-watch/
├── index.js                Host 入口：路由注册 + 60s 心跳调度
├── client.js               浏览器半边：侧栏图标 + 整页面板
├── host/
│   ├── store.js            JSONL 与 JSON 持久化（原子写、损坏自愈）
│   ├── collect/index.js    采集编排（单程 / 往返估算）
│   ├── collect/calendar.js L1：携程公开最低价日历
│   ├── rules.js            规则判定（冷却、滞回、日内合并）
│   ├── notify.js           飞书卡片 + 重试
│   ├── routes.js           HTTP 路由与同源校验
│   ├── page.js             独立只读 HTML 页面
│   └── util.js             日期、ID、日志等小工具
├── locale/{zh,en}.json     插件管理器的展示文案
├── icon.svg
├── cordis.patch.yml
└── README.md
```

设计文档（数据模型、采集层、通知规则、里程碑）见仓库 [`docs/design/price-watch.md`](../../docs/design/price-watch.md)。
