# 机票 / 酒店价格监控 · @ultraslow/dsh-price-watch

盯住机票和酒店的价格，价格有变化时通过飞书推送卡片。

机票有没有定日期决定它怎么工作：**没定日期 = 行情模式**，看未来约 380 天每天的最低含税价，点日历把某一天「钉住」变成监控，全程不需要登录；**定了日期 = 监控模式**，用你登录的携程会话读真实航班（航班号 / 航司 / 时刻 / 机场 / 机型）、每位乘客按身份能买到的含税实付价与余票。酒店是第三种监控：一家酒店 + 一段住期，读房型价格并记录「这段住期的最低整段总价」。

## 能做什么

| 能力 | 说明 |
| --- | --- |
| 机票行情 | 免登录读取携程未来约 380 天每天的最低含税价，单程一张、往返两张日历柱状图；最低价柱高亮，悬停看价格，点柱子就能「钉住这天」创建监控 |
| 机票监控 | 用登录态真实页面读具体航班与每位乘客按身份能买到的含税实付价（学生票 / 老年票 / 儿童票按带条件的票价产品筛选），并显示余票 |
| 往返对比 | 往返监控把「联程组合 vs 两段单买」摆在一起比，联程组合按实价升序最多 9 条；详情页拆成联程组合列表 + 去程表 + 返程表 |
| 酒店监控 | 城市 + 具体门店 + 住期 + 人数；按节奏读取房型价格，每次记录 1 个「该住期最低整段总价」价格点，并保存房型快照（房型 / 床型 / 面积 / 每晚 / 整段） |
| 酒店联想与校验 | 先选城市，酒店名输入 2 个字起边输入边联想该城市门店（↑↓ 选择、Enter 确认，选中即锁定门店 id）；创建前再到携程远端校验：查无 `HOTEL_NOT_FOUND`、多家 `HOTEL_AMBIGUOUS` 给出可点选候选、选中后又改名报 `HOTEL_LOOKUP_STALE` |
| 采集频率 | 30 分钟到 24 小时自选（默认 6 小时），调度带 ±15% 抖动；没有每日额度、没有静默时段；被风控挡住时该监控跳过一轮 |
| 走势图 | x = 采集时间，y = 最低可订价（酒店为最低整段总价）；最低点绿、最高点红；飞书卡片里的走势图是纯 JS 渲染的 PNG，不启动浏览器、无原生依赖 |
| 飞书卡片 | 每次采集尝试推一张，四区块：结论（价格 + 涨跌）/ 走势（图 + 统计）/ 明细（联程对比或航班表、酒店房型表）/ 采集信息；内容与上次相同不重复推，失败不重试 |
| 手机只读页 | `/price-watch/` 是独立只读 HTML 页面，同局域网手机直接打开，不依赖 DSH 前端 |
| 多语言 | 中英文界面，跟随 DSH 当前语言 |

## 安装方式

`<profile>` 换成你的 profile 名（例如 `desktop`、`web`）。

### 从 npm 安装

```sh
dsh plugin --profile <profile> add @ultraslow/dsh-price-watch
```

### 从源码安装

```sh
git clone https://github.com/Hankerlove/oh-my-dsh-plugin.git
cd oh-my-dsh-plugin
dsh plugin --profile <profile> add ./packages/dsh-price-watch
```

安装后用该 profile 启动 DSH，并刷新 Web UI 页面，左侧栏会出现价格标签图标。

卸载：

```sh
dsh plugin --profile <profile> remove @ultraslow/dsh-price-watch
```

### 可选依赖

插件用 `playwright-core` 驱动**你本机已安装的 Chrome**（不下载 Chromium）。没装 Chrome 或没登录时：行情模式照常可用（只走免登录日历），监控模式与酒店价格会显示「采集不可用」。

监控模式与酒店价格都需要**登录携程**：`设置 → 用户登录` → 点「登录携程」，在弹出的 Chrome 窗口里扫码 / 手机号登录（插件不接触密码和验证码），检测到登录态后窗口自动收走。登录态保存在插件自己的浏览器 profile 里，不写进任何 JSON，也不会动你日常用的 Chrome；删掉该目录等于退出登录。

## 使用

侧栏点开「价格监控」：顶部按「机票 / 酒店」分 tab，机票下再按「行情 / 监控」筛选。

要收飞书通知（机票与酒店共用），二选一：

- **企业自建应用（推荐，能推图）**：开放平台建应用 → 开 `im:message:send_as_bot` + `im:resource` 权限 → 发布版本 → 机器人拉进群 → 设置页填 App ID / App Secret / 群 chat_id → 点「发送测试消息」验证。
- **自定义机器人（最简单）**：群里添加自定义机器人 → 复制 webhook → 设置页填 webhook。这条通道不能推图片，卡片只有文字。

### 机票监控

#### 新建流程

`＋ 新建`：填出发地 / 目的地（三字码 `BJS` 或城市名「北京」都可以，会给出候选）→ 选单程或往返 → 决定要不要定日期 → 勾选乘客（没有的话先去 `设置 → 乘客` 添加，至少一位）→ 需要的话在「高级选项」里改采集节奏 → 保存后立即采一次。

#### 行情模式（没定日期）

不填日期时只追踪「未来一年每天最低价」：抓回约 380 天每天的最低含税价，画成日历柱状图。点某一天，再点「钉住」就能把它变成监控；往返会显示去程 / 回程两张日历，选了一侧后另一侧的非法日期会自动置灰。行情只做看板、不推告警（380 天里几乎每天都有新低，推了会被淹没）；往返的行情价是「去程最低 + 回程最低」相加的估算，真实往返价要靠监控。

#### 监控模式（定了日期）

单程填 1 个日期、往返填 2 个。之后每次都走登录态真实页面，读出具体航班与每位乘客能买到的含税实付价。详情页：结论（当前最低价 + 比上次涨跌）→ 走势图 → 往返对比卡 → 联程组合 / 去程 / 返程表 → 采集节奏 → 投递状态；右上角「立即采集」可手动跑一次。监控是纯实价口径：采集失败只记失败，不会拿日历估算价兜底。

#### 往返监控

往返会同时算「联程组合」和「两段单买」：联程组合按实价升序最多 9 条（每条是去程 + 返程完整组合），对比卡直接告诉你哪边更便宜、省多少。

### 酒店监控

#### 输入项

城市（复用机票那份城市库）+ 具体门店名 + 入住 / 离店日期（1–30 晚，离店必须晚于入住）+ 入住人数（1–6 人，固定 1 间）；采集节奏默认跟随设置里的监控节奏，可以不动。

#### 联想与校验

- 先选城市，酒店名输入 2 个字起边输入边联想该城市门店（名称 / 商圈），↑↓ 选择、Enter 或点击确认，选中即锁定门店 id；也可以不选、直接手填全名。
- 创建前到携程远端校验（纯 HTTP，不需要登录）：查无 → `HOTEL_NOT_FOUND`；只写品牌匹配到多家 → `HOTEL_AMBIGUOUS`，表单列出候选、**点一个就直接建那家**；选中门店后又改了名称 → `HOTEL_LOOKUP_STALE`，清掉已选门店让你重选。校验不通过不落库、不采集。

#### 采集结果

每次采集记录 1 个价格点：该住期的最低整段总价；同时保存一份房型快照。房型表按整段升序、最低价高亮，字段是 房型 / 床型 / 面积 / 每晚 / 整段。v1 **不区分**含早 / 可取消 / 会员价，也不做房型聚合去重。

#### 详情页

酒店抬头（名称 / 星级 / 评分 / 地址）→ 最低整段总价（+ 每晚约，右侧「立即采集」）→ 走势图 → 房型价格表 → 采集节奏（节奏 + 下次采集）。创建成功后页面显示「已匹配：酒店全名」。

## 数据与隐私

所有数据都在本机 `$DSH_HOME/price-watch/`（通常是 `~/.dsh/price-watch/`）：

```text
price-watch/
├── config.json      # 乘客名单、采集频率、通知设置
├── monitors.json    # 监控任务（机票与酒店）
├── state.json       # 调度游标、下次采集时间、登录态、投递状态
├── calendar/*.json  # 行情模式的整份日历快照
├── flights/*.json   # 监控模式最近一次采集到的航班快照
├── hotels/*.json    # 酒店模式最近一次采集到的房型快照
├── prices/*.jsonl   # 价格序列（机票监控与酒店共用同一套格式）
└── alerts.jsonl     # 最近的投递记录
```

- 行情只访问携程的公开日历接口：不需要登录、不读取你的订单、不上传任何数据。
- 监控与酒店都用你自己登录的浏览器会话，只读航班列表 / 房型价格与订单页税费，**永不提交订单、永不与验证码对抗**。
- 飞书凭据只存在本机 `config.json`，只用于发送卡片；接口读出来会脱敏（只回「是否已设置」），插件不读取你飞书里的任何内容。
- 出发 / 返程 / 离店日期早于今天的监控会被自动删除（不发卡片）。
- 删掉 `$DSH_HOME/price-watch/` 即可清空全部数据；登录态随同一目录删除即退出登录。

## 故障排查

| 现象 | 排查顺序 |
| --- | --- |
| 侧栏没有图标 | profile 里是否有 `link:` 依赖 → `dsh.profile.bundles` 是否含本包名 → 重启日志是否跳过该 bundle（`engines.dsh` 不满足会被跳过）→ 页面是否刷新过 |
| 面板打开但显示「读取失败」 | 打开 `http://127.0.0.1:<端口>/price-watch/api/status` 看返回；再看 DSH 终端里 `[price-watch]` 开头的日志 |
| 行情日历是空的 | 该航线可能没有报价，换个城市对试试。日历接口偶尔限频，等一个周期会自动恢复 |
| 监控模式一直失败 / 酒店提示「酒店价格需要携程登录」 | 没登录或登录过期：先 `设置 → 用户登录` 点「登录携程」完成登录，再回详情点「立即采集」；仍失败看详情里的上次失败原因 |
| 新建酒店时报 `HOTEL_AMBIGUOUS` | 携程匹配到多家分店：表单里点一个候选直接创建，或把酒店名写完整（带分店名 / 路名）再提交 |
| 新建酒店时报 `HOTEL_NOT_FOUND` | 该城市 / 日期段查不到这家酒店：确认城市选对、名字没有错别字；换个日期段或把名字写得更常见再试 |
| 飞书收不到 | 先在设置页点「发送测试消息」看原始错误：`code=… msg=…`。常见原因：Webhook 不是 `https://`、自定义机器人开了签名校验（本插件不支持签名）、自建应用没开 `im:message:send_as_bot` 权限、机器人没进目标群、chat_id 不对 |
| 显示「采集不可用」 | `playwright-core` 没装上，或本机没有 Chrome。重装插件即可；行情模式不受影响 |
| 早上看到「page.goto: Timeout …」或「网络不可用」 | 笔记本合盖 / 空闲休眠时系统只在维护唤醒里醒几秒，采集会因进程被挂起而超时。插件已识别这类失败：**不推失败卡**，只记到面板并在 **15 分钟后补采**；想通宵稳定采集就关掉系统自动睡眠 |
| 一直采不到、提示被风控 | 携程限频了，插件会让这个监控跳过一轮；持续被拦就把频率调大（比如改成 1 小时以上） |
| 点「登录携程」没弹窗 / 登录后仍显示未登录 | 先检查是否有残留 Chrome 进程占着 profile（`pkill -f price-watch` 后重试）、是否被安全软件拦截；登录后仍显示未登录就点状态条登录 chip 复查，或退出再登一次 |
